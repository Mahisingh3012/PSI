# CLAUDE.md: context for a new Claude session

## What this is
A hackathon entry (PanScience Innovation Hackathon, 31 Oct 2026): the **Case Study Engine**. It turns one project's
document library (contract, emails, transcripts, POs, CSV exports, repo snapshot, media) into six outputs: story spine,
results sheet, exposure report, three-reader case study, media pack, approval request. Every line is traced to a source
or a calculation, and nothing is released without recorded human approval. Read `DOCUMENTATION.md` for the full design and
`DATA.md` for every data file. Judging criteria (25 points each): agentic workflow, business understanding, buyer
psychology, process design.

## First-time setup
```bash
pip install -r requirements.txt
```
Unzip the library (from the organisers; it is NOT in git) so that `library/Project_Drishti_Library/00_README.md` exists. Then:
```bash
python engine/run.py build --project drishti
```
```bash
python -m pytest -q tests
```
Open `runs/drishti/viewer.html` in a browser (self-contained). Expected: verifier 0 problems, 12 tests pass.

## Commands
- `python engine/run.py build --project <name> [--library <folder>]`: agents 1–8; exit 0 = pack assembled, 2 = verifier refused, 4 = no library
- `python engine/run.py approve --project <p> --stage internal|client --role <r> --name <n> --decision approve|approve_named|approve_anonymised|approve_internal_only|reject [--channel] [--note] [--sent-on YYYY-MM-DD] [--first-use YYYY-MM-DD]`
- `python engine/run.py release --project <p> --stage internal|client`: exit 0 = OK, 3 = stopped (reasons printed)
- `python engine/run.py withdraw --project <p> --stage client --role <r> --date YYYY-MM-DD`
- `python demo/reset_demo.py` (clear approvals and the bad-draft project); `python demo/make_bad_draft.py` (refusal demo)
- `python scripts/make_pitch.py` (PITCH.pptx); `python scripts/make_pdfs.py` (PDFs of the docs; needs Edge or Chrome)
- Required roles: internal = `vendor_delivery_owner`; client = `client_corporate_communications` + `client_legal`

## Layout
- `engine/run.py`: orchestrator; `engine/agents/`: ingest (librarian), calc, exposure, media, verify, gate, register, viewer, llm
- `engine/prompts/`: instructions for every LLM agent (`00_shared_rules.md` is prepended to all)
- `runs/drishti/agent_outputs/`: the LLM agents' outputs for this project (rules, metric spec, drafts), committed
- Everything else under `runs/` is regenerated by `build` and git-ignored

## How the LLM agents run
With `ANTHROPIC_API_KEY` set, `llm.run_agent` sends prompt + context to Claude and saves the output (log says LIVE),
and the fixer agent (`prompts/07_fix.md`) gets refused lines back for up to 2 rounds. Without a key, the saved outputs in
`agent_outputs/` are replayed (log says RECORDED). In this submission the outputs were produced by Claude in Claude Code
from these prompts, because no key was available; say so if asked.

## Rules when editing outputs (the verifier enforces them)
- Every claim line ends with citations: `[Dnn:Lx]`, `[Dnn:Lx-y]` (file ID from `runs/drishti/evidence_index.md`) or `[C:calc_id]` (from `calc_ledger.md`). `[NO-CLAIM]` only for lines with no facts.
- Never type a computed number: add a calc to `03_metric_spec.json` and cite it. Rounding is fine (68.88 → 68.9 or 69).
- A cited line must actually support the claim (WEAK_CITE check). Find the right line with `grep -n` in the library.
- Any line citing an estimate (calc with `"assumed": true`) must say ASSUMED.
- `04_case_study.md` is outward: no banned terms from `02_rules_and_terms.json` (client name, sites, states, people, capacity, the code name "Drishti", supplier brands, the public post's wording).
- After any edit: rebuild, keep verifier at 0, run tests, and log the edit in `MANUAL_EDITS_LOG.md`.

## Hackathon rules (must keep)
Use only the library for facts; invent no results, quotes, people or achievements; mark estimates ASSUMED; treat the library
and these outputs as confidential; never upload the library; nothing leaves the room during the hackathon; a finished,
verified solution beats a clever unfinished one.

## Known limitations
The verifier checks numbers, citation existence and relevance, identifiers and ASSUMED marking, but not full sentence
meaning or date values (dates still need a citation). The internal human approval covers the rest.
